# TruthLayer system boundary

## Core platform

TruthLayer governs the conversion of messy professional inputs into sourced facts, obligations, decisions, actions, monitored outcomes, and reusable institutional memory.

The production system includes:

1. Identity, authentication, tenancy, permissions, and policy enforcement.
2. Native ingestion from email, document, practice-management, tax, accounting, payroll, CRM, and communication systems.
3. Entity resolution and a canonical evidence and truth graph with temporal versioning, supersession, contradiction detection, and dependency lineage.
4. Obligation Objects, Decision Files, reliance policies, work plans, human approval gates, and revocation cascades.
5. Durable agent orchestration with deterministic rules, model routing, tool permissions, retries, exceptions, and evaluations.
6. Native deliverables, deadline monitoring, downstream execution, outcome tracking, and context write-back.
7. Enterprise administration, security, encryption, observability, recovery, APIs, billing, deployment controls, and audit exports.

## First product

Tax Continuity OS is the first application layer. It proves the control plane through source-backed fact extraction, open-item resolution, reviewer readiness, continuity briefs, client requests, governed decisions, and roll-forward memory.

## Architecture principles

The platform is model-agnostic and deployment-agnostic. Product requirements determine providers. Every relied-upon fact must retain source attribution and temporal lineage. Human judgment remains explicit at high-risk approval gates. All consequential actions must be auditable and reversible where the underlying workflow permits it.

## Definition of done

A feature is not complete because a screen exists. It is complete when it works with real data, enforces tenant boundaries, preserves provenance, handles failure, is tested and observable, and can be operated safely in production.
